# Validação — F3-T01, F3-T06 e F3-T12 (9 nov. 2026)

Migrações `20261109130000_sessoes_tentativas_caderno_eventos.sql` e `…130500_indice_tentativas.sql`. Ainda não há questão publicada no banco real (a primeira publicação depende da revisão de Guto, F2-T15). Por isso, os testes de banco **publicam duas questões reais dentro de uma transação desfeita** e percorrem todo o fluxo como aluno A e aluno B; nada fica gravado.

## F3-T01 — Sessões e tentativas

| Caso | Resultado |
|---|---|
| Mesma ação de início duas vezes | Mesma sessão; 2 itens congelados; 1 evento de início |
| Sessão com item não publicado | Recusada |
| Resposta errada | Acerto calculado no servidor (falso); alternativa correta devolvida só agora; não repetida |
| **Mesma confirmação enviada duas vezes** | **Uma tentativa lógica**: `duplicate = true`, 1 tentativa, 1 evento de resposta, 1 entrada no caderno |
| Mesma ação com outra resposta | `resolve_action_reused` |
| Outra ação na mesma questão já respondida | `resolve_already_answered` |
| Ajuda vista antes de responder | Tentativa marcada com ajuda, mesmo com o cliente dizendo que não |
| Tempo total maior que a sessão; tempo ativo maior que o total | Ambos recusados (`resolve_time_invalid`) |
| Sessão pausada; simulado; prazo vencido | Resposta recusada se pausada; simulado não pausa; prazo vencido recusado |
| Encerrar duas vezes | Idempotente |
| Aluno B | Não vê sessões, itens, tentativas, eventos nem caderno de A; não responde, não registra evento nem muda motivo nas coisas de A; escrita direta na tabela negada |

Envios simultâneos (concorrência real) não foram exercitados: o MCP usa uma conexão só. A proteção é estrutural: trava da linha do item da sessão durante a confirmação + `unique (user_id, client_action_id)` + `unique (session_item_id)`. O teste concorrente via API fica para quando houver questão publicada.

## F3-T06 — Caderno de erros e motivo

| Caso | Resultado |
|---|---|
| Erro novo | Entrada criada com motivo `not_reported` explícito e sem data de motivo |
| Errar de novo a mesma questão em outra sessão | Mesma entrada (1 só), `wrong_count = 2`, primeira tentativa preservada e última atualizada; tentativa marcada como repetida |
| Acertar depois | Entrada continua ativa (a resolução é da agenda de revisão) |
| Informar motivo "errei a conta" | Gravado + 1 evento `motivo_informado` com `{"motivo":"calculo"}`; repetir o mesmo motivo não duplica o evento |
| Motivo fora da lista | Recusado |
| Voltar a "não informado" | Aceito; a data do motivo volta a nula |

## F3-T12 — Eventos de sessão

| Caso | Resultado |
|---|---|
| Lote de 4 eventos com 1 repetido | 3 gravados, 1 ignorado; reenvio posterior do mesmo identificador também ignorado |
| Ordem | Sequência contínua e única por sessão: `1 sessao_iniciada · 2 resposta_confirmada · 3 questao_aberta · 4 alternativa_marcada · 5 ajuda_vista · 6 resposta_confirmada` |
| Hora do cliente absurda (ano 2000) | Guardada como nula |
| Texto livre no conteúdo do evento | Recusado pela restrição do banco |
| Tipo gerado pelo servidor enviado pelo cliente | Recusado |
